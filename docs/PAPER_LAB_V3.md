# Paper Lab v3 — 독립 가설과 실제 예산을 분리한 검증

상태: 2026-10-08 구현, **명시적으로 실행해야 하는 paper 전용 실험**.
기존 `run`/병렬 v2/live 동작을 자동으로 교체하지 않는다. 신규 기준은 수익성이
검증된 최적값이 아니라, 가설을 고정해 비교하기 위한 초기 정책이다.

배포 전 주의: 당일 read-only API 점검에서 20종목 모두 시초 구간이 복원됐지만,
일부 호가 시각이 VM 시계보다 최대 약 6초 앞섰다. `w32tm /query /status`는
Local CMOS Clock과 미동기화 상태를 표시했다. 원인 전부를 단정하지 않으며,
VM/서버 시계와 호가 타임스탬프를 먼저 확인해야 한다. v3는 미래 호가를
`future_quote_clock_check_required`, 오래된 호가를 `stale_quote`로 구분하여 차단한다.
이 점검 때문에 시스템 시계를 임의 변경하거나 허용 오차를 늘리지 않았다.

## 확인된 문제와 데이터 계약

공식 [OpenAPI 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의
`Candle.timestamp`는 종목 1분봉 **종료 시각**이다. 구간은
`[timestamp - 1분, timestamp)`이다. `MarketIndicatorCandle.timestamp`는 시작 시각이다.
종목 시초 09:00~09:30 구간은 종료 시각 09:01~09:30의 30개 봉으로 구성한다.

2026-10-08 v2 기록 468회/4종목에 새 계약을 적용하면 시초 구간이 468회 모두
완전했다. 기존 불완전 판정은 이 시각 계약과 불일치했다. 단, 해당 기록의 호가는
사이클 시작보다 뒤에 조회되므로 과거 수익을 임의로 계산하지 않았다.

- 한국 시간으로 정규화. 미래·당일 외·비정상 OHLCV·상충하는 중복 봉 차단.
- 봉별 조회 시작 시각과 전체 수집 완료 시각을 구분. 조회 당시 미완성 봉은
  전체 수집이 끝난 뒤 시간이 지났다는 이유만으로 완료 봉으로 승격하지 않는다.
- 완료 봉은 일별 ledger에 보존. 조회 범위가 밀려도 시초 기준은 유지된다.
- 오후에 새로 등장한 종목은 공식 `before=당일09:30`/count=30 조회로 시초 봉을
  보완한다. 데이터를 만들어 채우거나 무거래 구간을 추정으로 연결하지 않는다.
- 최근 31개 봉의 연속성과 신선도를 검사. 데이터 부족은 전략 탈락과 분리한다.

## 전략과 후보 선정

현재 정책은 `config/paper_lab_v3.json`에 있다.

| 전략 | 구조 | 손절 기준 |
| --- | --- | --- |
| opening_control | 완료 봉으로 시초 고점을 처음 상향 통과 | 시초 고점 - ATR |
| pullback | 단기 평균 상승 추세, 3봉 눌림, 직전 고점 재돌파 | 눌림 저점 - 0.25 ATR |
| range_breakout | 직전 10봉 횡보 폭이 4 ATR 이내, 구간 고점 돌파 | 구간 저점 - 0.25 ATR |

ATR은 최근 14개 완료 1분봉의 true range 평균이다. 눌림과 장중 돌파에는 시초
박스 통과를 요구하지 않는다. 각 진입 시점의 기준·손절은 포지션에 고정한다.
기관 수급을 대변한다는 주장은 하지 않으며, 체결 압력·VWAP·호가 점수 중복 관문은
새 전략에 사용하지 않는다. live의 기존 필터는 변경하지 않는다.

랭킹 상위 최대 20종목을 읽는다(코드상 상한 30). 연구 단계에서는 주가 45,000원
상한이나 누적 거래대금 500억으로 먼저 제거하지 않는다. 종목 정보·경고·레버리지/
인버스 제한, 호가 신선도·스프레드와 최근 체결 가능성은 별도로 검사한다.
랭킹 범위 밖 종목까지 관찰했다고 주장하지 않는다.

초기 공통 기준: 최근 5분 거래대금 1억 원 이상, 직전 15봉 중앙값 대비 최신 거래량
1.2배 이상, 스프레드 최대 0.3%, 기준점 대비 최대 1.5 ATR 추격, 손절 거리 최대 2%.
`2 ATR >= 추정 왕복 비용의 2배`는 **가격 이동 여지에 대한 가설**이지
기대 수익 예측이 아니다. `cost_space`가 지나친 병목이면 단독 탈락 에피소드의
후속 결과로 검토하며, 당일 결과를 보고 몰래 수치를 조정하지 않는다.

시간대는 09:31~14:50(끝 시각 제외), 15:15부터 청산 시도,
15:40 runner 종료다. 기존 오후 매매 금지는 연구 가설에서 제외했다.

## 가상 계좌와 청산

각 전략은 연구 100만 원, 예산 제한 5만 원의 두 독립 계좌를 사용한다(총 6개).
이는 실제 계좌 잔고 조회가 아닌 **정책상 가상 자금**이다. 예산 제한 계좌는
기존 설정의 주문 금액·포지션 비율·일일 횟수 제한도 적용한다. 연구 계좌는
가상 자금 범위에서 일 최대 6회까지 허용한다. 동시에 계좌당 1개 포지션만 보유한다.

- 수량 = 현금·주문 상한·손절 시 비용 포함 위험·최근 거래대금 참여율(0.1%)·
  최우선 매도 잔량 참여율(10%) 중 최소. 1주가 안 되면 `budget_or_risk_or_depth`.
- 거래당 위험 0.35%, 일일 손실 1%를 초기 상한으로 사용하되 기존 설정이 더
  엄격하면 더 엄격한 비율을 적용한다. 연구 계좌 절대 일일 한도는 정책의
  `research_daily_loss_krw`(10,000원), 예산 제한 계좌는 기존 절대 한도를 사용한다.
  양쪽 모두 비율/절대 한도 중 작은 값을 사용하고 기존 이익 잠금도 적용한다.
- 매수는 현재 ask+불리한 슬리피지+수수료, 매도는 bid-불리한 슬리피지-비용.
- 손절을 넓히거나 물타기하지 않는다. 이익 1R 이상 진행 후 완료 봉으로 2 ATR
  되돌림을 확인하며, 30분 후 0.5R도 진행하지 못하면 시간 청산한다.
- 종목 재진입은 최소 30분 간격. 최우선 매수 잔량이 부족하면 전량 체결을
  꾸며내지 않고 포지션을 남겨 신규 진입을 막는다. 분할 청산은 아직 구현하지 않았다.
- 시세가 없으면 평가 손익은 마지막 값으로 남되 데이터 오류로 기록한다.
  청산 완료로 취급하지 않으며, 보유가 남으면 실험 완료 일수도 인정하지 않는다.
- API/평가 오류 연속 한도 도달 시 신규 진입 중단 상태를 재시작 후에도 유지한다.

호가/분봉 샘플 방식이라 틱 단위 MFE·MAE·슬리피지·부분 체결을 재현하지 못한다.
갭이 발생하면 계획한 손실을 초과할 수 있다. 실제 주문 API를 호출하는 경로는 없다.

## 평가와 기록

출력: `reports/paper_lab_v3/` (Git 제외).

- `manifest.json`: 코드 해시·유효 정책·기존 위험 제한. 달라지면 기존 출력에 섞지
  않고 실패한다. 새 실험은 새 출력 경로를 명시하고 과거 파일을 삭제하지 않는다.
- `ledger.json`: 6계좌·완료 봉·진입 에피소드·5/10/15/30분 결과·MFE/MAE·진행 일수.
- `comparison.json`: 순손익/거래당 손익/최대 평가손실/최고 수익 1·2건 제외 결과/
  날짜별 손익/슬리피지·수수료·세금 2배 스트레스/가용 데이터와 탈락 사유.
- `decisions.jsonl`: 모든 후보의 관측 시점별 판단. 반복 횟수와 독립 에피소드 수를 구분.
- `tapes/`: 원시 read-only API 응답과 수집 시각. `source/`에는 코드와 정책 사본.

구조가 발생한 에피소드는 매수하지 않아도 30분 동안 호가를 계속 수집한다.
단일 조건 탈락과 다중 조건 탈락의 후속 순수익률을 따로 묶는다. 이는 필터 제거
진단이며 대체 포트폴리오의 실현 손익이 아니다. 체크포인트를 90초 넘게 놓치면
나중 가격으로 메우지 않고 null로 남긴다. 최대/최소 유리 움직임은 관측된 샘플 기준이다.

운용 일수와 평가 유효성은 별개다. 실제 거래일·09:05 이전 시작·연속 기록·오류 없음·
당일 청산을 확인하고, 진입 시간대의 평가 가능 비율이 사이클별 80% 이상인 날만
진행 일수로 인정한다. 완전한 데이터로 탈락한 것은 정상 평가다. 5일 완료 후 신규
진입은 중단하며 자동 live 승격은 없다. 표본이 작으면 수익이 있어도 `hold_unvalidated`다.

## 실행 — 배포와 분리

아래 명령은 실행 안내이며 이번 코드 수정만으로 자동 실행되지 않는다.
기존 runner/예약 작업과 동시에 실행하지 않는다. 기존 예약 작업은 여전히 `run`
명령을 가리키므로, **v3를 검증하려고 기존 작업을 그대로 켜면 안 된다.**

```powershell
$env:PYTHONPATH = "$PWD\src"
# 주문·가상 체결 없이 API 수집 품질만 점검 (임시 폴더 사용)
.\.venv\Scripts\python.exe scripts/verify_lab_collection.py

# 기존 작업을 중지한 후 수동 paper 1회 / 반복 실행
.\scripts\stop.cmd
.\scripts\run.cmd paper-lab-once
.\scripts\run.cmd paper-lab-run

# 새 빈 디렉터리에서 순차 재현. 다른 코드 버전/기존 출력 경로는 거부
.\scripts\run.cmd paper-lab-replay --tapes reports/paper_lab_v3/tapes --output-dir reports/lab-replay-001
```

`paper-lab-*` 래퍼는 기존 watchdog pause를 해제하지 않는다. 새 runner는 기존
paper runner와 동일한 단일 실행 잠금을 사용하고, `stop.cmd`는 두 runner 모두
해당 프로젝트 경로에 한해 중지한다. v3 자동 실행 예약·watchdog 전환은 별도 배포
단계에서 확인해야 한다. 기본 v2 상태·기록과 live 코드 경로는 그대로 보존한다.

현재 배포 변경과 이후 작업은 [시장 맥락 및 복구 점검](PAPER_LAB_MARKET_CONTEXT_2026-10-15.md)에 기록했다.

### 2026-10-15 시작 시각 및 매수·매도 점검

평일 runner 예약과 watchdog 감시 시작을 09:04에서 **09:00**으로 변경했다.
프로세스 기동·API 지연이 있으므로 첫 데이터 저장이 정확히 09:00:00이라는
뜻은 아니다. 09:00~09:31은 수집/관찰, 신규 매수는 09:31 이상 14:50 미만이다.
최근 31개 연속 완료 봉이 없거나 미래/오래된/동일·역전 호가이면 진입하지 않는다.
상위 20종목에서 세 구조를 독립 평가하고 거래량 1.2배, 최근 5분 거래대금 1억,
스프레드 0.3%, 추격 1.5 ATR, 손절 거리 2%, 비용 여유 2배 기준을 유지한다.

매도는 구조적 손절, 1R 이상 상승 후 완료 봉의 2 ATR 되돌림, 30분 경과 후
현재 bid가 진입가+0.5R 이하인 무진전 상태, 15:15 세션 청산 또는 일일 손실
한도로 결정한다. 30분이 지났다는 이유만으로 모든 포지션을 청산하지 않는다.
시세가 유효하고 매수 잔량이 수량 이상이어야 모의 청산된다. 강제 청산 시각은
체결 보장이 아니며 runner는 15:40 종료, 리포트 예약은 15:42다.

오늘 15:08까지 연구 눌림목 2건은 structural_stop/completed_bar_trailing,
연구 횡보 돌파 3건은 no_progress_timeout이었다. 일일 한도에 의한 30초
조기 청산은 없었다. 횡보 돌파의 30분 청산 손실은 관찰됐으나 단일 일자의
결과만으로 시간 제한을 제거하지 않는다. 청산 후 가격과 비용을 포함한
대안 보유기간 비교가 필요하다. 이번에는 전략 코드·정책·원장 변경 없이
예약 시각과 회귀 테스트만 변경했으며 기존 운영 기록을 계속 사용한다.

### 2026-10-14 거래 위험과 일일 한도 정합성

연구 계좌에서 거래당 위험 0.35%(약 3,500원)와 기존 절대 일일 한도
1,000원이 충돌하여 두 포지션이 약 30초 만에 daily_loss_guard로 청산됐다.
사용자 승인으로 연구 계좌 한도를 당일 시작 자산 1%와 10,000원 중 작은
값으로 변경했다. 예산 제한 5만 원 계좌는 기존 1%/절대 한도 중 작은 값
(초기 약 500원)을 유지한다. `.env`와 live 위험 기준은 변경하지 않는다.

수량은 기존 제약에 더해 남은 일일 손실 예산으로 제한한다. 비용 포함 구조적
손절 손실과 현재 bid로 즉시 청산 시 손실 중 큰 값을 주당 위험으로 삼는다.
당일 이익으로 손실 예산을 확대하지 않는다. 갭·시세 지연·잔량 부족 때문에
실제 모의 손실이 계획 한도를 넘을 수 있으므로 한도 보장을 뜻하지 않는다.

장 종료·무보유 확인 후 기존 기록은
