# Portfolio overview

## 30초 소개

Toss Securities OpenAPI를 이용해 국내 주식의 단기 모멘텀 후보를 찾고, paper와
live 주문을 분리해 실행하는 안전 우선 자동매매 시스템입니다. 전략 자체뿐 아니라
계좌 상태 동기화, 주문 journal, 부분 체결·취소·재시작 복구, 일일 리스크 제한,
탈락 후보의 사후성과 추적까지 구현해 **운영 가능한 자동화 시스템의 신뢰성**을
다뤘습니다.

## 만들게 된 배경

초기 자동매매는 정해진 시간과 단순 모멘텀 조건에 크게 의존해, 짧은 보유 후 손절이
반복되거나 좋은 후보를 boolean filter 하나로 놓치는 문제가 있었습니다. 신호 기준을
계속 완화하면 진입은 늘지만 거짓 양성도 함께 늘어납니다. 따라서 다음 질문을 중심으로
프로젝트를 발전시켰습니다.

1. 시장 데이터나 주문 API가 불안정해도 계좌를 안전하게 보호할 수 있는가?
2. 진입하지 않은 후보까지 추적해 필터가 정말 유효했는지 검증할 수 있는가?
3. paper 실험이 검증 없이 live 주문으로 번지지 않게 구조적으로 격리할 수 있는가?
4. 장중 장애와 Windows 예약 작업 문제를 사용자가 계속 지켜보지 않아도 복구할 수 있는가?

## 해결 접근

### 안전장치를 전략보다 먼저 평가

레버리지·인버스 제외, stale data, 스프레드, 유동성, 현금, 포지션 수, 일일 진입과
손실 제한을 먼저 확인합니다. 점수가 높아도 안전 조건 하나가 실패하면 주문하지
않습니다. live 시작 시에는 계좌 보유·미체결·주문 가능 금액과 로컬 상태가 완전히
동기화된 경우에만 신규 진입을 허용합니다.

### 단일 조건을 다단계 점수로 개선

시초 박스 돌파 여부만 보던 구조에서 거래량, VWAP 이격, 호가 불균형, 체결 압력,
시장 국면을 각각 정규화해 최종 점수로 결합했습니다. Toss API에서 직접 제공하지
않는 기관 순매수 데이터는 “기관”으로 오인해 이름 붙이지 않고, 관측 가능한 값으로
구성한 proxy임을 코드와 문서에 명시했습니다.

### 실패 후보도 데이터로 사용

`filter_funnel`은 후보가 탈락한 단계와 당시 지표를 남깁니다. `shadow_tracking`은
주문하지 않은 후보의 5/10/15/30분 수익률과 MFE/MAE를 기록합니다. 이를 symbol/day
episode로 묶어 반복 관측이 표본 수를 부풀리지 않게 분석했습니다.

### 실험의 승격 경계를 코드로 표현

사후 검토에서 좋은 추세 지속 사례가 발견됐지만 표본이 한 건뿐이었기 때문에 live
규칙을 완화하지 않았습니다. 대신 높은 점수, 최근 돌파, 2개 봉 유지, 제한된 VWAP·
돌파 이격, 2회 연속 확인을 모두 요구하는 보조 경로를 paper에만 추가했습니다.
포지션의 5분·10분 재평가와 수익 보호도 같은 방식으로 paper에 격리했습니다.

## 주요 기술적 결정

| 문제 | 결정 | 이유 |
| --- | --- | --- |
| paper와 live 혼선 | broker와 전략 실험 경로 분리 | 검증 중 규칙의 실주문 전파 방지 |
| 주문 중 프로세스 종료 | 제출 전 pending journal 기록 | 중복 주문과 유실 상태 복구 |
| 로컬 상태 불일치 | live startup reconciliation | 계좌를 최종 진실의 원천으로 사용 |
| 기관 데이터 부재 | VWAP·호가·체결 proxy | API로 확인 가능한 데이터만 사용 |
| 과도한 필터 완화 | funnel + shadow episode 분석 | 거짓 양성과 놓친 기회를 함께 비교 |
| 장중 runner 중복 | single-instance lock + watchdog | 중복 주문과 무응답 운영 위험 축소 |
| 비용을 무시한 paper | adverse slippage + 비용 모델 | 백테스트 낙관 편향 완화 |

## 프로젝트 발전 과정

### 1. 실행 가능한 최소 시스템

OAuth, 시세·계좌 조회, 후보 스캔, paper broker, live 주문, 상태 저장과 CLI를
구성했습니다.

### 2. 주문·운영 신뢰성 강화

live 이중 잠금, 일일 손실 제한, pending journal, 주문 ID 저장, 부분 체결,
timeout 취소, 재시작 복구, single-instance runner와 비상 정지를 추가했습니다.

### 3. 시장 상황을 반영한 진입 구조

09:00~09:30 관찰 구간에서 시초 박스를 만들고, 오전·장 막판 진입 창을 분리했습니다.
거래대금 500억 원, 시장 국면, 적응형 거래량, VWAP·호가·체결 proxy를 단계적으로
평가하도록 재구성했습니다.

### 4. 관측 기반 paper 실험

후보 funnel과 shadow tracking을 추가해 진입 0건도 설명 가능한 상태로 만들었습니다.
주간 episode 검토를 거쳐 제한적인 추세 지속 보조 진입과 5분·10분 포지션 관리를
paper 전용으로 구현했습니다.

## 검증 방식

- API와 broker는 fake client로 테스트해 실제 주문 없이 오류·부분 체결·취소를 재현합니다.
- 전략 테스트는 경계값, 시간대, 필터 실패, paper/live 격리를 확인합니다.
- 변경 후 `compileall`, 전체 `unittest`, `git diff --check`를 수행합니다.
- 장중 결과는 날짜별 report와 로컬 상세 진단 자료로 분리해 보관합니다.
- 전략 변경 문서에는 관측 표본, 반례, 결정과 live 승격 조건을 함께 기록합니다.

## 이 프로젝트가 보여주는 역량

- 외부 REST API 인증·재시도·throttling과 응답 정규화
- 상태 기반 주문 수명주기와 장애 복구 설계
- 안전장치가 포함된 자동화 엔진과 paper/live 환경 격리
- 시장 지표의 점수화, 사후성과 추적과 근거 기반 실험
- Windows Task Scheduler·PowerShell을 포함한 운영 자동화
- 테스트 가능한 의존성 경계와 문서 중심의 변경 이력 관리
